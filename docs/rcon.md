# RCON 管理端口

JAR 在独立 TCP 端口（默认 8090）提供 UTF-8、逐行请求/响应的管理协议。它用于在不安装 Node/npm 的运行环境中新建博客、设置用户权限以及管理临时封禁。

RCON 不是 Minecraft 协议，也不是 HTTP API。端口不提供 TLS，因此只能绑定回环地址、受信任的管理网或 VPN，公网远程使用应通过 SSH 隧道。

## 配置

`.env` 与 JAR 放在同一工作目录：

```dotenv
RCON_ENABLED=true
RCON_HOST=127.0.0.1
RCON_PORT=8090
RCON_TOKEN=<足够长的随机令牌>
```

| 变量           | 缺省值      | 行为                                                        |
| -------------- | ----------- | ----------------------------------------------------------- |
| `RCON_ENABLED` | `true`      | 设为 `false` 时不启动管理端口                               |
| `RCON_HOST`    | `127.0.0.1` | 监听地址；直接运行 JAR 时保留回环地址                       |
| `RCON_PORT`    | `8090`      | TCP 端口，必须在 1–65535                                    |
| `RCON_TOKEN`   | 空          | 认证令牌；为空时端口仍可监听，但所有认证都会失败            |

Docker 发布端口时需要让容器内进程监听 `0.0.0.0`，同时将宿主端限制在回环地址：

```text
容器 .env: RCON_HOST=0.0.0.0
端口发布:  127.0.0.1:8090 -> 8090/tcp
```

不要配置为宿主 `0.0.0.0:8090 -> 8090/tcp`。局域网测试确实需要远程直连时，只绑定服务器的受信任内网地址，并用主机防火墙限制来源；测试结束后恢复回环绑定。

## 连接与认证

使用任意保持交互的纯 TCP 客户端连接，例如：

```bash
ssh -N -L 8090:127.0.0.1:8090 user@example-host
nc 127.0.0.1 8090
```

会话示例（令牌在交互中输入，避免把真实值写入文档或脚本）：

```text
OK imzako RCON; authenticate with: auth <token>
auth <RCON_TOKEN>
OK authenticated
help
OK 命令：...
quit
OK bye
```

- 认证前只能发送 `auth <token>`。
- 连续 3 次认证失败后服务端断开连接。
- 空闲读取超时为 2 分钟，单行最多 8192 字节。
- 成功响应以 `OK ` 开头，输入或业务错误以 `ERR ` 开头。
- `quit` 与 `exit` 会正常关闭当前会话。

## 命令

所有命令都可以省略或带上 `imzako` 前缀；例如 `new "标题"` 与 `imzako new "标题"` 等价。

| 命令                                            | 说明                                                      |
| ----------------------------------------------- | --------------------------------------------------------- |
| `help`                                          | 显示命令摘要                                              |
| `imzako new "博客名"`                          | 新建草稿                                                  |
| `imzako new "博客名" --tags "技术 Java"`      | 写入空格分隔的 tags                                       |
| `imzako new "博客名" --dir notes`              | 写入 `BLOG_DIRECTORY/notes/`                              |
| `imzako new "博客名" --publish`                | 新建后立即公开                                            |
| `imzako new "博客名" --draft false`            | 显式设置草稿状态；也接受 `true/false`、`yes/no`、`1/0`    |
| `op UID 1\|2\|3`                               | 设置普通用户、管理员或服主权限                            |
| `ban UID 小时数 "理由"`                        | 临时封禁；小时数必须在 1 到 87600，理由为 1–300 字符      |
| `pardon UID` / `unban UID`                      | 手动解除封禁                                              |
| `user UID` / `status UID`                       | 查询权限等级、封禁到期时间和理由                          |

带空格的标题、标签和理由必须放在单引号或双引号中。反斜杠可转义下一个字符。`op`、`ban`、`pardon` 和 `user` 都要求 UID 已存在，否则返回错误。

### 新建博客的输出

默认生成草稿，文件内容如下：

```markdown
---
title: 博客名
date: 2026-10-03 16-30
tags:
draft: true
---
```

日期使用应用所在时区，格式为 `yyyy-MM-dd HH-mm`。文件名从标题生成；同名文件存在时自动追加 `-2`、`-3`，不会覆盖。目标目录由 `BLOG_DIRECTORY` 决定，目录不存在时自动创建。

## 权限与封禁

| 等级 | 角色                         | 当前行为                                               |
| ---- | ---------------------------- | ------------------------------------------------------ |
| 1    | `USER`                       | 普通用户                                               |
| 2    | `USER`、`ADMIN`              | 管理员；当前预留给后续管理功能                         |
| 3    | `USER`、`ADMIN`、`OWNER`     | 网页博客管理面板和 `/api/blog/manage/**`               |

权限持久化到 MongoDB `admin_users`，封禁持久化到 `user_bans`。封禁中的用户仍能读取公开文章；等级 3 用户仍能读取管理列表，但博客新建、修改、删除会返回 403。未来聊天室、留言板和评论区实现写接口时，必须复用服务端的可写权限检查，不能只在前端隐藏按钮。

权限和封禁状态会在下一次 `GET /api/auth/me` 或受保护请求时从数据库刷新，不要求用户重新登录。过期封禁即使尚未被 MongoDB TTL 后台任务物理删除，也不会继续生效。

## 运维检查

上线后至少验证：

1. 未设置 `RCON_TOKEN` 时无法认证。
2. 未认证发送 `help` 得到 `ERR authentication required`。
3. 正确认证后 `user <测试 UID>` 返回等级和封禁状态。
4. `imzako new "部署自检"` 生成 `draft: true` 文件，且 front matter 的日期和标题正确。
5. 自检文章删除后，公开列表、管理列表和磁盘目录中都不留临时内容。
6. 宿主机公网网卡无法直连 8090；SSH 隧道或受信任内网入口可以连接。

日志只记录监听地址、客户端断开和内部异常，不应打印令牌。不要把真实令牌、客户端命令历史或包含凭据的 `.env` 提交到 Git。
